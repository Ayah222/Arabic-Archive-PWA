UNREAD COUNT BADGE
==================

Display a small badge (counter) on top of the bell icon.

Requirements:

* The badge shows the number of unread notifications.
* "Unread" includes BOTH new and old notifications that the user has not opened yet — it is not limited to newly arrived ones.
* The badge must update in real time as notifications are read or as new ones arrive.
* If unread count is 0, hide the badge completely (show only the bell icon).
* If unread count is large (e.g. more than 9), display "9+".

Badge Style:

* Small circular/rounded badge.
* Positioned at the top corner of the bell icon (adjust position correctly for RTL).
* Color must follow the COLOR CONSISTENCY rules below (do not introduce a random/unrelated red or pink that clashes with the existing status badge palette).
* Must remain readable and properly sized on mobile/responsive view.

COLOR CONSISTENCY WITH EXISTING STATUS BADGES
==============================================

The Notifications feature (bell badge count, severity indicators, dropdown items, full notifications page) must visually match the EXACT color language already used by the existing status badges across the app — the same ones used for:

* Project status badges (e.g. "نشط" / Active, "مكتمل" / Completed) in the "أحدث المشاريع" (Latest Projects) table.
* Project type badges (e.g. "صحي", "تجاري", "تخطيط عمراني").

Requirements:

* Reuse the SAME badge component/style already used for these status pills: soft, low-saturation pill-shaped backgrounds with a matching, slightly brighter text/icon color on top — NOT solid, high-saturation, alarming colors.
* Do NOT introduce a new "loud" red or pink tone for the unread count badge or for severity indicators if it does not match the existing badge tone family already used in the app (in Dark Mode the soft glassy pill tones, in Light Mode the muted pastel pill tones).
* Map notification severity to the closest EXISTING status color family already defined in the design system instead of inventing new colors:
  - Informational notifications → reuse the same tone family as a neutral/active status badge (e.g. the tone used for "نشط").
  - Warning / "ending soon" notifications → reuse the same tone family as a caution-style badge already present in the app (e.g. the tone used for project types like "تخطيط عمراني" or any existing amber/teal warning tone in the design system).
  - Expired / critical notifications → reuse the same tone family as the existing most urgent status badge already present in the app (e.g. the tone used for "تجاري" or any existing rose/red badge already part of the palette), kept at the SAME saturation level as that existing badge — not a brighter or harsher red.
* The unread count badge on the bell icon may use a slightly more saturated version of the existing "urgent" badge tone so it stays legible at a small size, but it must stay within the same color family/hue as the existing badges — not a new unrelated red.
* In Dark Mode: match the existing dark-mode badge treatment (deep tinted background + bright tinted text, consistent with the glassy navy-based card system).
* In Light Mode: match the existing light-mode badge treatment (very light tinted background + saturated tinted text, consistent with the soft pastel card system).
* Before implementation, inspect the existing badge component(s) used for project status/type and reuse their exact Tailwind classes/CSS variables for the notification severity indicators and the unread badge — do not hardcode new hex values.

NOTIFICATIONS DROPDOWN
======================

When the user clicks the bell icon:

Open a dropdown panel (not a full page navigation).

Dropdown Content:

* Header with title: "التنبيهات" (Notifications).
* List of the latest 10 notifications, sorted Newest First.
* Each notification item must display:
  - Icon or severity indicator (warning, info, expired, etc.) using the color-matched badge styles defined in the COLOR CONSISTENCY section below — not new/unrelated colors.
  - Notification title/message
  - Related entity name (e.g. contract/registration name)
  - Time/date or "ends in X days" / "expired since X days" text (reuse existing alert text logic)
* Unread notifications must be visually distinguished from read ones:
  - Example: unread items have a subtle highlighted background or a small dot indicator; read items appear neutral/dimmed.

Footer:

* A clickable link/button at the bottom of the dropdown labeled:
  "إظهار جميع التنبيهات" (Show All Notifications)
* Clicking it navigates to a full Notifications page (or opens a full list view) showing ALL notifications, not just the latest 10.

Dropdown Behavior:

* Opens on click, closes when clicking outside or pressing Escape.
* Must support RTL layout and scroll properly if content overflows.
* Must adapt to Dark Mode and Light Mode (background, borders, text colors, hover states).
* Smooth open/close animation consistent with other dropdowns/menus already in the app.

READ / UNREAD BEHAVIOR
======================

When the user clicks/opens a specific notification (from the dropdown or from the full notifications page):

* Mark that specific notification as "read".
* Decrease the unread badge count by 1 immediately (no page reload needed).
* The notification remains visible in the list, but now appears as "read" (dimmed/no highlight).

When the user clicks "إظهار جميع التنبيهات" and opens the full notifications page:

* Opening the full list does NOT automatically mark all notifications as read.
* Only individually opened/clicked notifications get marked as read.

Optional but preferred:

* Add a small action in the dropdown header or full page: "تحديد الكل كمقروء" (Mark all as read), which sets unread count to 0.
